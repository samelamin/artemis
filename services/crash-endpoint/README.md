# crash-endpoint

Cloudflare Worker that accepts manually-uploaded diagnostic reports from the
client. Stores them in R2 and rejects anything outside a 2 MB body cap, a
per-IP rate limit, and a global daily KV budget. This is the Wave 4
implementation of the diagnostic-reports feature described in
`docs/plans/2026-09-04-diagnostic-reports.md`.

The Worker only accepts `PUT /v1/report`. There is no read path — the bucket
is write-only from the internet. Reports are retrieved with
`wrangler r2 object get` from a machine holding the account credentials.

## One-time setup before first deploy

The KV namespace id is generated by Cloudflare and must be pasted into
`wrangler.toml` after creation. The R2 bucket and its 30-day lifecycle rule
must also exist before first deploy:

```
wrangler kv namespace create DAILY_BUDGET_KV
# paste the returned id into wrangler.toml's [[kv_namespaces]] id field

wrangler r2 bucket create vbt-reports

wrangler r2 bucket lifecycle add vbt-reports --id expire-30d --expire-days 30
```

The rate limiter binding needs no pre-creation; `namespace_id` in
`wrangler.toml` is just an integer naming this rate limiter within the Worker.

## Credentials

`CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` must be present in the
deploying environment (e.g. via a local `.env`, which `.gitignore` already
excludes). `wrangler.toml` deliberately omits `account_id` so it falls back
to the `CLOUDFLARE_ACCOUNT_ID` env var at deploy time. No credential,
account identifier, or endpoint secret belongs in any committed file in this
directory — this repository is public.

## Local validation (no deploy)

```
npm install
npm run typecheck
npm test
```
